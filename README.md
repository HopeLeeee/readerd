# ReaderD

配合 [ReaderC](https://github.com/HopeLeeee/readerc) 使用的 Windows 纯净文献阅读器。当前为 **0.2.7 开发预览版**。

## 启动

推荐使用 **安装版 `ReaderD-Setup-0.2.7.exe`**：安装向导可选择安装目录，并创建桌面与开始菜单快捷方式，之后直接启动已安装的 `ReaderD.exe`。安装版设置保存在 Windows 用户数据目录，卸载默认保留设置。Zotero 中选择安装目录里的 `ReaderD.exe`。

项目也支持 **ZIP 绿色版**：解压一次，在目录中运行 `ReaderD.exe`，整个文件夹一起保留。它的配置在同目录的 `ReaderD-data`，适合移动使用。每版提供的下载文件以 Release 附件为准；0.2.7 提供安装版。

单文件便携版便于临时分发，但每次运行需要解包，不推荐用作 Zotero 的长期打开程序。0.2.4 本机两轮对比：单文件冷启动约13–17秒、已有窗口转交约33秒；目录版约2.4–3.5秒和1.1–1.3秒。同一核心代码，仅包装形式不同。

源码开发可用 `npm install`、`npm start`；`npm run dist` 构建安装版、ZIP 与单文件三种产物。旧版运行时先保存并关闭旧窗口，再启动新版。升级时在 Zotero 重新选择新版的固定 EXE 路径。

## Windows 提示与签名

便携版没有商业代码签名证书，Windows SmartScreen 首次运行时可能显示“未知发布者”或“Windows 已保护你的电脑”。这是未签名程序的通用提示，不等于检测到病毒；源代码和构建脚本都在本仓库。可选择“更多信息 → 仍要运行”，并用 Release 中的 SHA-256 核对下载文件。要彻底消除该提示，需要为 EXE 购买并配置 Authenticode 代码签名证书。

## 首次启动

首次启动会先展示快捷键一览，按 Ctrl + Enter 进入 AI 连接设置。必须成功测试 API 服务或本地 Codex 后才能完成引导；引导期间 Esc 不会关闭窗口。命令行传入的 PDF 会等引导完成后再打开。完成一次后，以后启动直接进入阅读界面，可用 Ctrl + 逗号重新修改。

## 绿色版数据

ZIP 和单文件绿色版把配置放在 **EXE 同目录的 `ReaderD-data` 文件夹**，不再写入 `%APPDATA%`：

```text
ReaderD-0.2.7.exe
ReaderD-data\
  settings.json
  ai-key.bin
  reading-profile.md
  gloss-cache.json
  Local State
  Cache\ 等运行缓存
```

- 第一次运行 0.2.7 时，如果 `ReaderD-data` 还没有配置，会从旧的 `%APPDATA%\readerd` 迁移 `settings.json`、`ai-key.bin`、`reading-profile.md`、`gloss-cache.json` 和 `Local State`，不会覆盖 `ReaderD-data` 中已有文件。
- 移动软件时，把 EXE 和 `ReaderD-data` 文件夹一起移动即可保留设置、词表和缓存。
- 删除 `ReaderD-data` 相当于清空本软件的配置、阅读画像、词表和词释缓存。
- 如果 EXE 所在目录不可写（例如放在 `C:\Program Files`），会自动回退到 `%APPDATA%\readerd`。
- `ai-key.bin` 由 Windows `safeStorage` 加密，与当前 Windows 用户绑定；换电脑或换用户后需要重新填写 API Key。
- `gloss-cache.json` 含目标词、原句片段和中文释义，只保存在本机。
- 每篇 PDF 的 `.readerd-original.pdf`、`.readerd-state.json`、`.readerd-annotations.json` 仍放在 PDF 旁边，不进入 `ReaderD-data`。
- 仍可用 `READERD_USER_DATA` 环境变量指定其他数据目录，优先级高于绿色目录。

源码开发模式（`npm start`）继续使用 Electron 默认的 `%APPDATA%\readerd`，不影响已安装的绿色版数据。

源码开发：安装 Node.js 后在此目录执行：

```powershell
npm install
npm start
```

Electron 下载若受网络影响，可以为安装配置可信镜像。依赖版本由 `package-lock.json` 锁定；已安装的本地运行包经过 SHA-256 清单校验。

## 阅读

启动窗口保持居中，上下留白为 0.1.7 版本的三分之一。按原先上下各 40px 的屏幕计算，新版各留约 13px。

PDF 页与页之间不添加间距，连续紧贴显示，保留 PDF 自身的页内空白。

无标题栏、无工具栏、无窗口控制按钮。左右章节和推荐模块使用原来的浅灰绿色背景（#f1f2ee）与 16px 圆角，和中央阅读区顶部对齐。三栏各占独立区域，中央 PDF 放大时在阅读区内横向滚动，不会被两侧模块遮挡；窗口缩小时同样保留栏间距。窗口其余空白区域保持透明，PDF 页面本身保留原始白纸背景。顶部 15 像素区域可拖动窗口。正文单列连续滚动，没有页码跳转功能。目录已加宽并减小层级缩进，自动忽略首页论文题目。

未打开文献时，中央首页也使用相同的浅灰绿色背景与圆角，覆盖中央阅读区，打开 PDF 后取消此首页背景。左右模块根据内容自动增减高度，最低为 220px，最高为窗口高度；超过后在模块内部滚动。

文字批注输入框和偏好面板用 Ctrl + Enter 保存，Esc 取消。文字批注用选中文字末尾右上角的小棕色圆点标记（4px，不加粗）。鼠标悬停圆点时显示带实体浅灰绿色背景的批注卡片，移开即关闭；双击圆点可以编辑。文字批注不再用虚线标记或依赖无底色的系统提示。鼠标侧键默认按钮 4 为上侧键、按钮 3 为下侧键，可在偏好中交换；驱动若重映射为其他按键，需要调整驱动设置。

新批注的圆点锚定选区最后一个可见字符，距文字末尾约 2px，缩放后仍使用相同的小间距。旧批注按已有选区矩形兼容定位。

## 批注如何保存

- 高亮与下划线写入源 PDF。文字批注写在文末新增的批注页，源文选区附注释及链接；批注页可以链接回源位置。中文内容使用 Windows 本地中文字体嵌入。
- 编辑后延迟约一秒自动保存，也可立即 Ctrl + S；退出前等待保存完成。
- 首次保存会创建 `论文.pdf.readerd-original.pdf`，以后从此原稿重建，避免反复保存产生重复高亮或批注页。
- `论文.pdf.readerd-annotations.json` 和 `论文.pdf.readerd-state.json` 用于恢复可编辑批注、位置与目录。**移动文件时一起移动原稿备份和这两个 JSON。**源 PDF 本身包含最终可见标注和批注文字，可单独交给其他阅读器查看。
- ReaderD 编辑时载入原稿备份并恢复交互标记，因此文末批注页不重复显示在正文滚动区；悬停原文末尾的棕色圆点查看批注卡片，双击编辑。导出的 PDF 同样使用小棕色圆点，并保留批注文字与附页链接。
- 当前高亮还包含绘制外观，不能保证在其他阅读器中删除其原生批注后同时清除外观。外部编辑原 PDF 与 ReaderD 重建保存之间尚无合并机制。

## 章节与引用

有 PDF 书签时读取页码和标题位置，保留命名目标、XYZ、FitH 等目标坐标，并根据当前缩放定位到章节处。书签仅提供页面时，在该页匹配对应标题，支持跨行章节名；找不到可靠匹配时保留页级定位。没有书签时先使用版面识别；配置 AI 后根据章节候选提取真实标题与层级，输出必须匹配源文本，并缓存识别结果。没有 AI 配置也能阅读和使用版面目录。

数字制引用支持方括号、列表、范围和保守的独立上标识别。悬停展示该处全部条目，过长时内部滚动。保留题名中 `E. coli` 等缩写之后的完整内容，不再显示“查看原文条目”。点击题名打开 DOI 页面，不显示 DOI 字符串；PDF 未提供 DOI 时，仅在点击后将该条题名、作者、年份提交 Crossref 查询，唯一可靠匹配后打开系统浏览器。网络失败或匹配不明确时显示提示。缺失条目与上标歧义会明确提示。当前参考文献解析是启发式方法，复杂格式可能漏提或字段拆分不正确；作者—年份制和扫描件 OCR 暂未实现。

## 兴趣与固定 Markdown 文件

按 Ctrl + 逗号可查看固定文件的实际路径，通常为 `%APPDATA%/readerd/reading-profile.md`。

```markdown
# readerd 阅读画像

- 身份：研究生
- 研究方向：微生物代谢
- 感兴趣的主题：NAD, nicotinamide, 肠道菌群

<!-- readerd:auto:start -->

此区域由应用维护最近阅读记录。
<!-- readerd:auto:end -->
```

可直接编辑身份、方向和主题，或者在偏好面板填写。自动区域之外的其他手写内容会保留。标记已读时写入题名、章节主题和批注信号；应用最多保留 100 条近期记录，并给予新近记录更高权重。当前推荐采用透明的关键词匹配，候选仅来自本篇参考文献，去重后固定最多三条；不足三条时显示实际数量。没有历史时使用填写的方向和兴趣，均未填写时退回当前文献题名。不会声称读过被引论文的摘要或全文。

## ReaderC 与 AI

复用 ReaderC 实际核心代码及其原始 363,525 条词频索引、55,084 条词形映射，附来源 commit 与许可。词库用于候选判断和词形还原；中文上下文释义由用户配置的 Chat Completions 兼容模型提供。熟词与生词状态保存在本应用设置中，**当前未与 Zotero 实时同步**。

AI 配置使用服务基础地址（如 `https://服务/v1`）或完整 `/chat/completions`、模型名和 API Key。密钥由 Electron `safeStorage` 使用 Windows 系统加密保存，不写入阅读画像。留空密钥保留现有配置。

AI 连接方式也可以选择本地 Codex。留空程序路径时会自动查找 Codex Desktop 安装的最新 CLI（包括 `bin` 下带版本号的子目录），也可以手动填写 `codex.exe` 的绝对路径。调用使用 Codex 已有登录状态，仍需联网并消耗账户额度，不会读取当前聊天。程序以只读沙箱、临时会话、忽略用户配置和规则的方式启动 Codex，测试连接会实际发送一次最小请求，因此断网或额度耗尽时会提示失败而不是假装成功。

AI 章节识别发送章节候选文本与页面位置，悬停词释发送目标词及其所在句；不会发送 PDF 文件。打开或滚动到页面后，程序会在约 60 毫秒后提前预取可见正文与附近一屏的候选词释义（最多 6 个请求同时进行，邻页最多占用两个名额），悬停时优先读取缓存，未命中才单次请求。API 与 Codex 模式每页最多预取 100 个候选词，每 12 个词合并一个请求，各词保留自己的句子、目标位置与编号；连续失败会暂停预取 30 秒，避免反复请求。切换文献、页面卸载或退出时，会取消旧页的 HTTP 请求及 Codex 子进程，立即释放预取名额；旧结果不再写入缓存。

首次悬停优先立即显示本地 ECDICT 词义，仅在释义开头用小红点标记；后台 AI 返回后替换为语境释义并去掉红点，不显示来源文字。词典查不到的词保留等待提示，AI 失败时保留本地词义；词典多义不会写入上下文缓存。

缓存命中时取消固定悬停等待，立即显示；只保存校验合格的上下文词释，最多 5000 条，存于用户数据目录的 `gloss-cache.json`，重新打开仍可复用。缓存按服务、模型、原句与目标位置隔离，不把同一个词在不同语境下的释义混用。首次阅读尚未预热的内容仍需等待模型，尤其 Codex 冷调用可能需要数秒；词典参考与 AI 结果明确区分。

词释请求复用 ReaderC 的 `requestBody` / `batchRequestBody`：按句合并多个词，关闭推理（`reasoning_effort: none`、`enable_thinking: false`），单次限制 64 tokens，批量按词数限制输出长度，跨句时为每个目标单独提供上下文。服务明确拒绝可选参数时，仅移除该参数后重试，并按地址和模型缓存兼容结果；鉴权、额度和普通服务错误不会触发兼容重试。连接测试使用实际词释请求，避免仅通用请求能成功而词释失败。返回结果须为有效、简短的中文释义，截断或格式错误不缓存，下次悬停可以重试。远程服务需要 HTTPS，本地服务允许 HTTP。PDF 渲染、批注、规则目录、引用与基础推荐不需要联网。

只有带浅绿色虚线的候选词会触发悬停释义。没有虚线的普通词（例如常见的 `connects`）悬停不会发请求，也不会出现“释义加载中”；仍可用上侧键或下侧键将其标记为熟词/生词，标记后才进入候选词流程。

AI 接口测试使用本地模拟服务验证目录来源约束、后台批量预取、悬停命中缓存、无虚线词不触发释义和中文词释，不代表已验证真实模型识别质量。构建后的 Windows 可执行程序也通过桌面测试。

截图输出到 `test-results/`。生成的示例文献和 DOI 仅用于交互测试，不是实际学术引文。真实出版社论文、复杂版式、超长文献性能和实际 AI 服务输出质量仍需进一步验证。

结构：`electron/` 为文件与窗口宿主；`src/app.mjs` 为阅读界面；`src/analysis/` 为文献结构解析；`src/words/` 为 ReaderC 适配；`src/profile.mjs` 为 MD 画像；`src/geometry.mjs` 为 PDF 坐标变换。
