# Desktop persistence

- `preload.cjs` exposes an allowlisted `window.readerd` bridge. Renderer code has no Node access. PDF paths are accepted for saving only after a native open dialog authorized that file in this process.
- New annotations set `coordinateSpace: 'pdf'`. Their rectangles use **actual PDF user-space coordinates in points, with a bottom-left origin**. `src/geometry.mjs` converts viewport rectangles with the inverse PDF.js viewport transform, handling rotations and crop-box offsets without guessing a MediaBox height. `pdfRectToViewport` converts them back for display. Legacy records without `coordinateSpace` retain their original top-left convention.
- First save creates `<paper>.pdf.readerd-original.pdf` without overwriting it. Each later save reconstructs the annotated document from this pristine source; deleted annotations therefore disappear and repeat saves do not duplicate note pages. `openPdf()` loads the pristine bytes when this backup exists, while keeping the selected document's path. The UI restores interactive overlays from the state file. The selected on-disk PDF contains exportable annotations and visible note pages.
- Text notes are placed on appended pages, with a source-page/coordinate label and return link. The corresponding selection links to the note and receives a standard PDF text annotation. This first implementation deliberately uses the permitted appendix option because unused page margins cannot be reliably inferred from selection rectangles.
- Highlights and underlines have flattened visible appearances plus standard annotation metadata. Written annotations remain visible in PDF readers regardless of text-layer handling. The editor uses the pristine source to avoid drawing their saved appearances twice.
- State recovery lives in `<paper>.pdf.readerd-state.json`; normalized saved annotations live in `<paper>.pdf.readerd-annotations.json`. Keep these and the original backup alongside the PDF when continuing edits. Do not modify the original backup externally.
- Reading profile has a fixed path under Electron's `userData`, `reading-profile.md`. `saveProfile({ markdown, automaticOnly: true })` replaces only the `readerd:auto` block, preserving user-written text. Passing a string means an explicit full-file edit.
- API credentials use Electron `safeStorage` in `ai-key.bin`; public settings JSON does not contain the key. Model requests accept only configured endpoint/model and explicit payload text, require HTTPS except loopback, block redirects, and time out after 60 seconds.
- On native close, `onBeforeClose(callback)` lets the renderer flush pending work. After success call `windowAction('close')` to finish closing. A renderer save failure may keep the window open for recovery.
